# Repository working rules

## Code style

- Match the naming, idiom, and structure of surrounding files.
- Keep comments short and only document constraints the code cannot show.
- Keep lists, labels, IDs, paths, user-facing copy, permissions, and numeric constants in configuration, data files, enums, or named constants.
- Do not leave dead code, commented-out code, stray TODO items, or speculative abstractions.

## Process

- Codex is authorized to create commits and push this repository to its configured remote when doing so is part of the requested workflow.
- Never force-push or rewrite published history unless the owner explicitly requests it.
- Do not run asset builds or development servers. The owner compiles and starts them manually.
- Before writing code, read the nearest existing example and follow its conventions.
- After changes, run the narrowest relevant check and report the actual output.
- Ask one concise question before coding when a requirement is materially ambiguous.

## Output

- Keep explanations short and include relevant file paths.
